## Assessment

The defensible contribution is a reproducible, retrospective case study of how explicit actuator direction, held-reading provenance, persistence and cooldown change authorization counts. The current manuscript generally states that scope accurately. It does not demonstrate an improved detector, physical fault prevention, measured actuator behavior or causal crop benefit. The negative LiveGate result should remain central rather than being repaired through repeated reuse of the revealed evaluation windows.

The manuscript's principal audit counts agree with the current CSV tables on inspection: naive pH 655/125 total/flagged, range-plus-persistence 417/0; naive CO2 2149/219, range-plus-persistence 456/9. The disjoint flag categories, the nine heuristic-spike CO2 commands, unavailable-direction handling and sample-based occupancy denominators are visible in the implementation and outputs. This is consistency evidence; an independent rerun is still required. The source-day bootstrap correctly pools numerator/denominator counts and pairs methods in the inspected follow-up code and tests.

## Findings, in priority order

1. **Novelty has not been established against the nearest literature.** `Paper Files/main_audit.tex:64` proposes a gap between sensor detection and executable commands, but `Paper Files/audit_references.bib` omits directly relevant hydroponic FDD from 2003 and 2025 and CEA residual-based isolation from 2026. The narrower command-accounting question may remain useful; sensor-to-actuator reliability in agriculture is established work. Compare questions, required information and endpoints explicitly before making a Q1 novelty claim. Do not compare this benchmark's command rates with another study's classification accuracy as if they rank methods on one endpoint.

2. **The main practical zero-count result has no sensitivity envelope yet.** The statement that range checks plus persistence remove flagged pH/EC authorizations is accurate for the reported log and setting. `scripts/68_deployment_audit.py:81` fixes hold age at 64 s, lines 104–116 fix persistence at 32 s and use the configured 600 s cooldown; `_spikes` fixes an eight-scale cutoff. Changes can reschedule cooldown opportunities and change the source readings supplying commands. Report the original setting plus a complete, separately declared sensitivity grid before interpreting it as a design guideline that transfers to other settings. An out-of-range count should stay separate from bound/spike flags throughout.

3. **The controlled comparison supports a local negative result, with weak external precision.** `scripts/38_replay_reanalysis.py:74` selects evenly spaced candidates from non-overlapping, gap-free windows. This is systematic selection, not a random sample of deployments. Each split uses only 1,920 source rows before expansion into sensors and scenarios. Forty variants of a source window do not create forty new backgrounds. The manuscript already identifies eight windows and seven evaluation days (`main_audit.tex:137`), which is appropriate; add exact sampling fractions/exclusion coverage in the research ledger. Percentile intervals conditional on seven days and fixed selected settings cannot justify prospective superiority, prove equivalence, or account for adaptive hypothesis selection.

4. **The liveness conclusion depends on a restricted fault construction and a costly refusal rule.** At fixed epsilon, `LiveGateModel.survival` is a per-sensor run cap; the fixed comparator selects one cap shared across sensors. Beating that global cap would not establish a new fault-identification principle. The follow-up correctly discloses this and its coverage cost. A 30-sample held value can also be a valid quantized trajectory; the original background is a surrogate and can contain unknown faults. Whole-log liveness additionally joins filtered training values and carries run counts across gaps (`src/aasvr/livegate.py:130`, `:149`), already acknowledged at `main_audit.tex:154`. Preserve that disclosure; do not silently fix the frozen method and relabel its results as confirmation.

5. **Ancillary historical wording can mislead a reader even though the current paper corrects it.** `docs/livegate/RESULTS.md` calls temporal-coincidence counts authorizations on fault evidence and calls bound readings certain faults. The follow-up protocol and current manuscript explain why both descriptions are too strong. The research package should clearly direct readers to the correction without overwriting the frozen protocol or original numeric outputs. `main_audit.tex:205` should continue to describe logged temperature excursions with unresolved cause: no independent calibration or actual cooling duty was observed.

6. **One bibliography error is directly verified.** `audit_references.bib:83` gives four incorrect SensorTalk given names. The publisher lists Yi-Bing Lin, Yun-Wei Lin, Jiun-Yi Lin and Hui-Nien Hung. Correct the record from the primary publisher page. Other bibliography records were read but not exhaustively validated by this reviewer.

## Minimum decisive work

For the current retrospective claim, predeclare a small pilot sensitivity grid around the exact audit rather than tune a new detector: persistence 16/32/64/96 s, held age 32/64/128 s, cooldown 300/600/1200 s and spike cutoff 6/8/10. Publish every resulting command count and its disjoint source flags, including regressions and nulls; separate original from exploratory settings. Use the pilot's measured runtime only to decide whether the complete grid fits resources. Success means the main scoped interpretation survives or is narrowed to its observed boundary; no p-value or new winner is required. Also rerun the original preprocessing and main audit from public raw bytes with hashes and versions. These runs establish reproducibility/robustness, not fresh confirmation.

For a stronger physical claim, the missing evidence cannot be manufactured by replay. The cheapest next physical experiment is a frozen, bounded benchtop acid/base or water/concentrate dosing loop with independently calibrated pH/EC references, timestamped issued commands, observed relay/current or delivered volume, and known injected measurement faults plus legitimate steps. Compare naive, range-plus-persistence and one fixed candidate at matched useful-action opportunities. Randomize/repeat complete sessions, identify independent run units, and choose a precision target before collection. A single session or seven plants sharing one treatment apparatus cannot identify a crop benefit. Equipment, reference calibration, safe dosing supervision and authorization for a new collection are required; no cost was incurred here.

## Focused original-description provenance check

At the primary agent's request, the reviewer read only physical text-extraction lines 290–710 of `/tmp/hydro-root-paper.txt`, supplied as the extraction of `Automated_Hydroponics_Paper__Measurement_.pdf`. This is a passage-level text check, not a full original-PDF or rendered-layout review. These passages include the earlier device/dosing descriptions and the sensing/actuation method. The active audit passages at `Paper Files/main_audit.tex:115`, `:129`, `:139`, `:225`, `:241`, `:366` and `:369` and the complete `scripts/68_deployment_audit.py` were compared.

**Material qualification required:** the frozen audit's fourth arm is an approximate legacy **sensing-gate proxy under the common replay controller**, not a verified reconstruction of the deployed actuation algorithm. Original extraction lines 630–677 (printed manuscript lines 437–463) define alpha-dependent bands centered on the lower and upper limits, with widths `alpha * xi`, followed by a consecutive count for values within `zeta`. The prose and notation `[zeta_lower, zeta_upper]` do not uniquely resolve how those two interval bands were combined. The original does not describe this as the audit's generic out-of-band persistence rule. `scripts/68_deployment_audit.py:94`–`:116` never uses alpha: it estimates xi/psi, maps psi to `psi * 16` elapsed seconds, and calls `authorize` on an eligible held estimate. That is not necessarily a run of consecutive newly accepted measurements. The already disclosed development re-estimation is another approximation. Thus current wording asserting that the deployed rule required psi consecutive accepted out-of-band readings is too definite.

The source describes 10 min mixing lockouts explicitly after pH dosing (extraction lines 335–344; printed 255–264) and EC dosing (lines 352–359, continued at 405–406; printed 270–279). Its air cooling, CO2 injection and water-chiller descriptions contain no corresponding 600 s lockout. `configs/experiments/livegate.yaml:11` and `scripts/68_deployment_audit.py:81` apply 600 s across all five controlled channels and all arms. Extending that separation to CO2/cooling is a replay assumption, not a documented deployed timing fact. Absence from the retained description does not prove that the original hardware had no such behavior; it means the manuscript cannot attribute it to measured or verified firmware provenance.

The frozen numerical results need not change to correct this. They remain command counts under a specified common replay law. The whole-log sensitivity already shows consequences of varying its cooldown, but it does not validate the omitted alpha bands or reconstruct actual historical actuation. In particular, the 13 out-of-range CO2 authorizations must be attributed to the proxy; the reset mechanism alone does not establish that the full deployed actuation loop would have issued those commands. This qualification affects the first-season-style naive interpretation too: the reported counts simulate its general threshold style under the shared audit timing, rather than recover historical commands.

Minimal manuscript wording recommended for the control description:

> The original description specifies a 10 min post-dose mixing lockout for pH and EC. Its error-resilience method combines a sensing-reliability gate and rejection reset with alpha-dependent actuation bands around the setpoint limits and a within-band repeatability count. Equivalence between the retained description and the replay implementation is unverified.

Minimal wording for the audit methods, retaining the published beta values and existing numerical settings elsewhere:

> All arms use the reported setpoint limits, installed actuator directions and a common 600 s minimum separation between commands per channel. The 600 s separation is documented for pH/EC dosing; its application to CO2 and cooling is a replay assumption. Arm (iv) is an approximate legacy sensing-gate proxy using the published beta values and development-estimated xi and psi. It omits the original alpha-dependent actuation bands and uses psi times 16 s as out-of-band persistence of an age-eligible held estimate under the common controller.

Use **“Legacy-gate proxy”** for arm (iv) in current prose/table labels, while explaining any retained frozen figure/output label. Replace the result sentence's subject with “The legacy-gate proxy” and the causal clause with “In this proxy, the rejection-reset mechanism permits out-of-range readings to become accepted sources.” In the abstract, replace the implication that all timing was deployed with “Replay applies the reported setpoints, installed actuator directions and a common cooldown assumption.” One limitations sentence can state: “The legacy comparator omits the original alpha-dependent actuation bands, and cooldown outside pH/EC dosing is assumed; these counts do not reproduce verified firmware commands.” The controlled benchmark should likewise call its 10 min cooldown a shared benchmark setting.
